# Herdr 앱 독립 운영

Herdr 앱은 `hc`를 사용하고 TUI는 `herdr`를 사용합니다. 기본값은 TUI입니다. 앱은 별도 설정·작업 기록·설계 경로를 명시하며, 기존 TUI 작업·소유권·승인을 복제하지 않습니다. 공통 정책과 인증 프로필은 참조할 수 있지만 실행 세션이나 계정 사용 한도가 분리되는 것은 아닙니다.

## 설정과 실행

기존 예제 설정을 저장소 밖의 GUI 전용 위치에 준비하고 `runtime_backend`를 `core`로 지정합니다. `herdr_session`과 TUI `dashboard_workspaces`는 가져오지 않습니다. `private_plan_root`도 GUI 전용 경로로 지정합니다. 작업 기록 경로는 모든 명령에 명시하세요.

```sh
python3 teamkit_cli.py --config ~/.config/herdr-team-kit-app/config.json --state ~/.local/state/herdr-team-kit-app/state.sqlite doctor
```

실행 제어는 실제 core terminal 안에서 수행합니다. `hc run --bg -- ...`로 controller를 시작하면 core가 `HC_TERMINAL_ID`를 제공합니다. 이 변수를 수동으로 만들지 않습니다. `create`, 계정 한도 admission, `dispatch`, `receipt`, `park`, 검증과 인계는 기존 절차를 따릅니다.

`dispatch TASK --terminal TERMINAL`은 이미 열린 plain leader 대화를 재시작 없이 연결합니다. core·미연결 leader·명시한 cwd/model/effort·idle/PID·GUI 작업 기록 쓰기 경로의 명시적 허용을 확인하고 기존 owner label이 있으면 거절합니다. label 전 intent를 기록하고 `receipt`가 실제 실행 프로필과 계정을 확인해야 수신 완료가 됩니다. 기존 세션에 새 sandbox나 모델 설정을 적용하는 기능이 아닙니다. TUI 작업이나 연결 설계 실행은 채택할 수 없습니다. 결과 불명은 재전송하지 않습니다.

## 운영 현황 mod

`app-mods/team-operations`를 사용자 mod 폴더로 복사하고 `local.json`을 별도로 준비합니다. 이 파일은 공개 저장소에 추가하지 않습니다.

```json
{
  "python": "/srv/example/venv/bin/python",
  "script": "/srv/example/kit/teamkit_app.py",
  "config": "/srv/example/gui/config.json",
  "state": "/srv/example/gui/state.sqlite",
  "bindings": "/srv/example/gui/bindings.json"
}
```

bindings는 `version: 1`, `actions_enabled` boolean, 설정의 모든 팀을 포함한 `teams` 매핑, 선택적인 `inventory` Markdown 경로를 받습니다. 각 팀은 `label`, 실제 `terminal` 주소, 앱 `space` ID를 갖습니다. 고정 작업 표는 `ID | 이름 | 상태 | 완료 조건` 네 칸으로 읽습니다. 경로와 실데이터는 로컬에 둡니다.

mod는 GUI 작업 기록 JSON을 조회하고 core 상태를 별도로 표시합니다. 조회는 모델을 호출하지 않으며 작업 기록을 생성하지 않습니다. 누락된 상태·한도를 idle이나 0%로 추정하지 않습니다. 제품 진행률은 기존 승인 단계의 가중치를 사용합니다. `monitor`도 GUI 설정/작업 기록을 명시해 별도로 실행합니다.

```sh
herdr-app check ~/.config/herdr-app/mods/team-operations
herdr-app status
herdr-app shot /tmp/team-operations.png
```

초기 검사만으로 비동기 상태나 실제 화면을 검증했다고 쓰지 않습니다. 기본 layout/mod를 변경할 때는 복제본을 사용합니다. `lab-rich` 등 사용자 테마는 mod의 `theme()` 색으로 따릅니다.

## 승인과 재개

설계 읽기는 plan과 contract의 범위·필수 조건·완료 단계를 함께 표시합니다. 승인은 선택한 revision/digest와 현재 파일을 트랜잭션 안에서 대조하고 명시적인 확인을 요구합니다. 승인 버튼이 구현을 자동 배정하지는 않습니다.

재개는 core 작업 기록의 동일 owner를 가진 parked leader, 또는 정지·체크포인트가 기록된 handed-off 실행만 대상으로 합니다. 확인 후 실제 core controller를 시작하며 요청 접수와 수신·실행 결과는 다릅니다. 중복·대기·결과 불명인 요청을 자동 재실행하지 않습니다. `app-actions`에 보존한 결과와 작업 기록을 먼저 대조합니다. TUI retire 경로는 core terminal을 종료하지 않습니다.

## 검증 한계

단위 검사의 subprocess 대역은 argv/상태·소유권 계약을 확인합니다. 실제 프로필·core·모델·receipt·앱 렌더는 별도 통합 검증이 필요합니다. `hc label`에는 compare-and-set이 없으므로 협력 controller의 로컬 잠금과 변경 후 identity 대조를 사용하며 외부 직접 label 변경과의 원자성을 보장하지 않습니다. 작업 기록 밖의 직접 실행 작업과 다른 실행 환경의 활성 작업은 이 admission이 통합 제어하지 않습니다.


상단 운영 바는 같은 소스를 `team-overview`라는 별도 mod 이름으로 설치하고 `props.role: "overview"`로 배치할 수 있습니다. 운영 바의 layout 높이는 최소 166px로 확보합니다. 글꼴의 실제 줄 높이와 고정 행 높이를 명시해 상태 글자의 위아래가 잘리지 않도록 합니다. 전체 현황은 `team-operations`를 사용해 명령 수신 범위를 분리합니다. `local.json`의 `dashboard_tab`, `overview_font`로 전체 현황 이동 대상과 운영 바 폰트를 지정합니다. 총괄은 GUI 복구 기록과 실제 core 소유권에서 찾으며, 최초 대상은 bindings의 `coordinator`에 둡니다. 전체 현황의 별도 입력 설정은 pane의 `props.local` 경로로 선택할 수 있습니다.

재개 요청은 선택한 owner와 attempt를 controller의 CLI까지 전달합니다. `tell --expected-owner ... --expected-attempt ...`와 `dispatch --expected-attempt ...`는 바뀐 선택을 작업 기록 변경 전에 거절합니다. core의 정상 `done`은 대기 상태로 허용합니다. 설치된 hc에는 `--if done`이 없어 이 경우 identity/상태 대조 뒤 일반 send를 사용하며, blocked를 강제로 통과시키거나 전송 실패를 반복하지 않습니다. 외부 직접 입력과의 원자성은 제공하지 않습니다.


## 총괄 창을 닫았을 때

운영 바는 연결된 총괄의 실제 core 상태를 확인합니다. 살아 있으면 같은 창으로 이동하고, 닫힌 것이 확인되면 확인을 거쳐 GUI 체크포인트를 읽는 새 총괄을 엽니다. 복구 요청·생성한 terminal·소유권·계정 확인과 체크포인트는 GUI 작업 기록 옆에 저장합니다. 진행 중이거나 결과 불명인 복구는 중복 시작하지 않습니다. core 연결 실패는 종료로 추정하지 않습니다.

설정의 `coordinator`에는 `provider: "codex"`, model/effort, GUI `private_plan_root` 안의 `root`, 지침 파일을 지정합니다. 새 총괄은 최신 구독 한도를 확인하고 GUI 기록만 읽습니다. 제품 작업은 자동 재개하지 않습니다. 종료된 대화 전문의 복원이나 core 재시작 후 쉘로 바뀐 프로그램의 자동 재실행을 보장하지 않습니다. 다른 프로그램이 남은 총괄 자리는 먼저 보존하고 확인합니다.

## 네 계정 사용량

계정별 수집 결과와 각 시간 구간을 따로 표시합니다. 5시간·주간 값에는 비례 막대와 %를 함께 표시하며 70% 미만은 녹색, 70% 이상은 주황색, 90% 이상은 빨간색입니다. 지난 기록은 회색으로 구분합니다. 이 표시 기준은 수집·배정 정책을 바꾸지 않습니다. 조회 성공·제공 안 함·조회 실패·지난 기록을 구분하며 없는 값을 0%로 표시하지 않습니다. 마지막 관측 시각은 화면 새로고침이나 로그인 확인만으로 연장하지 않습니다. Codex 공식 조회가 5시간 구간을 반환하지 않으면 해당 칸은 제공 안 함입니다.

사용량 갱신은 모델 요청 없이 공식 CLI 조회를 수행합니다. Claude는 별도 임시 CLI의 내장 `/usage`만 사용하고 자신의 임시 세션만 정리합니다. 시작 화면·계정·준비 상태를 확인하지 못하면 이유와 조치를 표시합니다. 수동 표시 기록은 배정에 사용하지 않습니다. GUI가 직접 소유한 공식 `/usage` 조회에서 계정·양 구간·관측 시각·토큰 0·세션 정리를 검증한 기록은 `claude-native-usage`라는 별도 배정 근거로 사용합니다. 응답 연계 출처로 바꾸거나 초기화 시각을 추정하지 않으며, 기존 TTL과 각 구간 90% 미만 기준을 적용합니다. 회사→개인→대기 순서를 유지하고 TUI에는 적용하지 않습니다. `usage_probe_root`는 검증용 로컬 폴더로 지정합니다. 기존 사용자 설정이나 전역 hook을 변경하지 않습니다.

GUI Claude 실행은 프로세스별 `--settings`로 GUI statusline 수집기를 연결합니다. `claude_display_commands`에 계정별 기존 표시기를 지정할 수 있으며 TUI 수집기로 전송하는 표시기는 그대로 재사용하지 않습니다. 모니터의 주기 조회는 새 모델 대화나 반복 `/usage` 세션을 만들지 않습니다.

운영 보드는 처리할 작업을 먼저 보이고 완료된 고정 작업 목록은 펼쳐 볼 수 있습니다. 계정 상세에는 수집 출처·시각·누락 사유와 다음 조치를 표시합니다. 중요한 팀 이름은 크게, 이동 버튼과 보조 정보는 작게 표시합니다. 원래 고정 작업 ID와 미완료 항목은 접기 상태에서도 보존합니다.


## 작업 보드와 상세 조회

작업 보드는 상태별 칸반으로 조회합니다. 카드를 열면 작업 목적·담당 팀·연결된 실행과 설계를 확인할 수 있습니다. 설계는 상세 모달에서 필요할 때 읽고 닫으며 비어 있는 문서 영역을 상시 배치하지 않습니다. 조회와 창 이동은 상태 변경이나 제품 구현 승인이 아닙니다. 승인·재개는 기존 문서 버전·해시·소유권 확인을 유지합니다.

`work-detail --work ID`는 선택한 GUI 작업 기록 작업만 조회합니다. 실제 session의 owner/task/name/PID/provider를 대조한 경우에만 해당 실행으로 이동할 수 있습니다. 연결 실패는 종료로 추정하지 않고, 소유권 없는 과거 실행을 현재 작업으로 표시하지 않습니다. 카드의 모델과 effort는 요청값임을 구분합니다.

팀장의 작업 중 표시는 현재 native 상태가 working일 때만 Herdr 기본 Agents 목록과 같은 `mods/workspace-chrome/spinner.svg`·900ms 네이티브 회전으로 표시합니다. 작업 기록의 running만으로 작업 중을 추정하거나 고빈도 JavaScript 타이머로 화면을 다시 그리지 않습니다.

팀장 카드는 현재 앱 상태별로 준비한20개 문구를 사용합니다. 업무 중에는 집중 모드 켰어요·열일 중이에요, 대기에는 다음 타자 주세요·부르면 바로 여기요처럼 표시하며, 확인 요청과 새 답변은 각각 해당 의미를 유지합니다. 관측 시각45초 단위와 팀별 고정 오프셋으로 문구를 고르므로 같은 구간의 재렌더링에서는 흔들리지 않습니다. 기존 상태 갱신을 이용하며 별도 문구 타이머는 없습니다. 상태 확인 불가는 고정 안내를 유지합니다.

보조 문구는 연결된 업무의 시작 준비·요청 전달·진행·검토 대기를 구분하며, 세부 정보가 없으면 응답 준비나 다음 요청 대기로 안내합니다. 확인되지 않은 조사·구현·테스트 활동을 꾸미지 않습니다. 새 답변은 제품 작업 완료를 뜻하지 않으며 확인 후 앱의 대기 상태를 따릅니다.

제목·상태·진행률·남은 작업 수 같은 짧은 UI 문구는 단어 중간에서 줄을 나누지 않습니다. 의미 단위 자식으로 나누거나 행을 쌓아 공간이 줄어도 문구 전체가 다음 행으로 이동하게 합니다. 필수 작업 수·대기 이유를 숨겨 문제를 피하지 않습니다.

운영 바의 새 응답 알림은 `agents().status`의 화면별 읽음 상태를 사용합니다. core의 `done`은 마지막 턴의 결과이며 읽지 않았다는 뜻이 아닙니다. 해당 팀장 대화를 확인하면 앱의 `idle`을 따라 대기로 표시하고, 같은 공간의 다른 세션 상태를 팀장 상태로 대신 표시하지 않습니다.

운영 현황 상단은 `팀 운영 현황`과 앱 상태별 개수·총괄 연결 상태를 기본 표시합니다. 정상 연결의 복구 이력과 분리 정책 설명은 반복하지 않습니다. 총괄의 비정상 상태·복구 실패·실제 작업 대기 사유는 유지하며, 보류 사유는 해당 칸반 카드에서 확인합니다. 전체 진척률의 계산 기준과 고정 작업 목록은 정본에 유지합니다.

팀장 실행 상태·요약 상태·칸반 개수는 같은 20px 높이의 뱃지로 표시합니다. 상태 요약은 Needs you/Working/Done/Idle 네 가지로 나누고 0개일 때도 해당 테마 색을 유지합니다. 네 상태 이외 값은 미확인으로 별도 표시합니다. 상태 의미·읽음 계약·작업 완료 조건은 변경하지 않습니다. 뱃지는 상태 표시이며 누를 수 있는 실행 버튼처럼 표시하지 않습니다.

팀장 이름 앞 상태 점은 표시하지 않습니다. 실행 중 네이티브 애니메이션은 상태 뱃지 안에서만 표시합니다. 상단 글꼴은 로컬 `overview_font`로 지정하며 전체 운영 보드의 글꼴과 별도로 적용합니다.

확인 카드는 짧은 작업 요약과 작업별 질문·선택지를 보여줍니다. 선택지를 누르면 담당자·요청 내용·실제 처리 범위를 설명하는 모달이 바로 열리며, 모달의 명시적 확인에서만 요청 전달 또는 설계 승인을 수행합니다. 기본 흐름에는 별도 사유 입력·저장·기록 조회 단계가 없습니다. 설계 승인은 해당 버전의 진행 허가이며 실제 작업 배정과 구분합니다. 선택·취소·Esc·바깥 클릭은 요청이나 승인을 실행하지 않고, 처리 확인 후에는 모달을 자동으로 닫습니다.

비공개 bindings의 `card_prompts`는 짧은 요약, `card_decisions`는 카드별 `prompt`와 2~6개 `options`를 지정합니다. 각 선택지는 `id`, `label`, `description`, `intent`(`approve`, `changes`, `defer`, `confirmed`)를 갖습니다. 작업 카드는 `document`에 `revision`, `digest`, `phase`를 지정해 현재 설계와 연결합니다. 버전·내용·단계가 바뀌면 이전 선택지를 숨기고 재작성을 요구합니다. 범위를 바꾸는 선택은 `changes`로 설계 보완을 요청하며, 기존 설계를 그대로 승인하는 선택과 구분합니다. 잘못된 유형·중복 ID·운영 카드의 설계 승인 선택지는 거절합니다.

칸반과 카드 상세는 backend의 같은 `interaction` 판단을 사용합니다. 카드·문서 버전과 질문 ID/버전이 일치하는 전송은 ‘전달 준비 중’, ‘전송 확인 중’, ‘담당자 처리 대기’로 이동하며 같은 선택을 다시 요구하지 않습니다. 전송 결과 불명과 읽지 못한 기록은 ‘확인 필요’에 남기되 행동은 ‘전달 기록 확인’입니다. 새 문서나 새 질문에 과거 답변을 물려주지 않습니다. 전달 확인·총괄용 확인 기록은 업무 완료나 설계 승인을 바꾸지 않습니다. 정본의 완료 항목은 ‘완료로 기록됨’으로 표시하며 검증한 진척률로 추정하지 않습니다.

담당자는 전달 메시지에 포함된 `card-receipt --request-id … --task … --owner … --attempt … --outcome responded|deferred --answer-text …` 명령으로 처리 요약을 남깁니다. 현재 공식 팀장의 관리 터미널·실행 신원과 실제 수신 소유권이 모두 맞아야 기록됩니다. 응답 근거는 전송 이력과 별도로 보존하므로 늦은 응답을 연결해도 원래 timeout/unknown을 덮어쓰거나 재전송하지 않습니다. 처리 결과는 ‘담당자 응답 확인됨’ 또는 ‘보류 접수됨’으로 표시하고 업무 단계 갱신과 구분합니다.

상단은 조회 성공·일부 자료 미확인·갱신 실패와 마지막 관찰/수신 시각을 표시합니다. 15초 넘게 새 자료를 받지 못하면 갱신 지연을 표시하며 이전 자료를 유지합니다. 카드 조회 도중 버전이 바뀌거나 기록을 함께 읽지 못하면 동기화 확인으로 표시하고 실행 버튼을 막습니다. 팀장 상태 집계는 owner·task·name·PID·provider 신원을 검증한 대화만 사용합니다.

업무 단계가 진행 중이어도 구현 작업이 검토·배정 대기로 기록돼 있으면 칸반은 해당 대기로 표시합니다. 실행 중인 구현 요청 기록이 없으면 상태 확인이 필요하다고 표시하며 사용자 결정 질문을 새로 만들지 않습니다. 진행 중인 카드에는 실제 담당자가 준비한 유효한 결정 질문이 있을 때만 선택을 표시합니다. 그 밖에는 작업 요약·진행 상태를 보여줍니다. 작업 범위·담당·세션·기술 내역은 ‘상세 정보’, 이전 답변·초안·전달 이력은 ‘기록’에서 펼칩니다. 이전 요청이 전달 중이거나 결과가 불명확하면 새 전달을 막으며, 같은 선택 모달의 중복 클릭은 새 요청을 만들지 않습니다. 실패·결과 불명은 성공으로 닫지 않습니다.

5초 주기 조회는 기존 내용·초안·펼침·스크롤 영역을 유지합니다. 처음 읽을 때만 로딩 상태를 표시하고, 같은 정보·같은 오류에서는 재알림하지 않습니다. 조회 시각만 바뀌는 응답은 표시 변경으로 보지 않으며, 사용량의 관측 경과는 분 단위로 비교합니다. 실제 업무 변경·오류·복구는 반영합니다. 이 비교는 표시 알림에만 사용하고 카드 버전·승인 해시·백엔드 검증 데이터는 그대로 유지합니다.

설계 읽기는 `TextView.markdown`의 서식 보기로 시작합니다. 본문은14px·23px 줄 높이·최대880px 폭이며 모달의 스크롤 영역 안에서 흐릅니다. 원문의 일반 줄 구분은 보기용 hard break로 보존하되 fenced/indented code는 그대로 둡니다. 원문·버전·digest는 바꾸지 않습니다. 원문 보기 버튼만300px 읽기 전용 코드 뷰로 전환합니다. 링크는 명시적 HTTP(S) 클릭만 시스템으로 넘기고 다른 scheme은 열지 않습니다. Orca의 React 기반 편집기 코드는 이 mod에 포함하지 않습니다.

문서 영역은 Pretendard Regular(400)를 기본으로 사용하고 구역 제목은 Semibold(600), Markdown 제목과 강조는 렌더러의 기본 계층을 따릅니다. 원문 코드 보기에는 D2Coding12px을 적용합니다. 로컬 `document_font`·`document_code_font`로 문서 글꼴만 바꿀 수 있으며 상단 보드의 D2Coding과 팝오버 UI 글꼴은 독립적으로 유지합니다.

요약의 Needs you는 앱 blocked, Working은 working, Done은 읽기 전 done, Idle은 idle입니다. 색은 현재 테마의 blocked/working/done/idle을 따르고, 총괄 연결 상태는 이 집계에 포함하지 않습니다. 이 개수는 연결된 제품 팀장만 대상으로 하며 제품 업무 완료 건수와 다릅니다.

상태 요약 뱃지는 네이티브 Popover로 팀장 목록을 엽니다. 현재 앱 상태로 필터링하며 항목 선택은 해당 팀장으로 초점만 이동합니다. 다시 누르기/바깥 클릭/Esc/닫기로 닫습니다. 0개는 빈 목록 안내를 표시합니다. 펼침은 32ms 단발 준비 후 높이220ms/투명도150ms 네이티브 전환이며 반복 JS 애니메이션 타이머는 없습니다. `team-operations.status-idle` 등 네 상태 명령도 같은 열기 경로를 사용하고 `team-operations.close-status`는 닫습니다.

상태 팝오버 전체는 Herdr UI 글꼴(settings().ui_font, 미지정 시 Geist)을 명시해 제목·목록·빈 상태의 글꼴 계열을 통일합니다. 상단의 overview_font 설정은 별도로 유지합니다.

카드 상세는 UI 글꼴 Geist(설정된 ui_font가 있으면 해당 글꼴), 본문12px/줄높이18px·제목15px를 명시합니다. 카드 ID·실제 상태·담당 팀장 또는 총괄·확인할 이유·연결 세션을 함께 표시합니다. 운영 환경 구축 항목은 제품 구현 세션으로 임의 연결하지 않습니다.

총괄용 확인 선택은 확인 기록만 저장합니다. 저장 후에는 총괄 확인 대기이며 작업 완료·설계 승인·에이전트 전달로 표시하지 않습니다. 자동 갱신 중 카드 버전이 바뀌면 작성하던 답변의 저장을 막고 다시 확인하게 합니다. 설계 승인·재개는 기존 문서 버전/해시/owner/attempt 검증을 유지합니다. 카드 모달은 바깥 클릭과 Esc로 닫히며 닫는 것만으로 답변을 제출하지 않습니다.

설계 문서를 읽으면 본문 위쪽에 300px 문서 영역을 확보하고, 모달 크기 변경 시 본문 스크롤 높이를 다시 계산합니다. 설계 편집기의 글자는12px이며 읽기 전용·줄바꿈을 적용합니다. 자유 입력은 단일 `--answer-text=...` 인자로 전달하여 옵션처럼 시작하는 답변도 그대로 저장합니다.

문서와 상세 내용은 마우스 휠·네이티브 스크롤바를 사용하는 구성입니다. 별도의 PageUp/PageDown 버튼이나 단축키를 등록하지 않습니다. 모달 본문 스크롤 영역과 스크롤바는 같은 ID에 명시적으로 연결합니다.
