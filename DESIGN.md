# Team operations interface

This is a native macOS Herdr GPUI surface. It inherits the host theme; the captured board uses a dark background, darker column wells and lighter cards and controls. Colors come from `theme()` roles rather than a separate web palette. There is no browser CSS layer.

The board is an operational workspace. Its reference is Notion's property-oriented board organization: a card exposes useful attributes and opens a focused detail view. It groups by responsibility for the next action: agent waiting, observed execution, operator decision, and completed or organized records. Operational errors remain with the responsible agent; they do not create an operator choice.

The board has four columns: 담당자 대기, 진행 중, 내 결정 필요 and 완료·정리. At widths below 900px, columns stack vertically; wider layouts give populated columns the remaining space and keep empty or collapsed columns compact (165px). Completed records start collapsed. Cards and columns use 8px corners; cards have 12px internal padding, while columns use 8px padding.

Cards show a short title and explanation, the responsible person, current activity and current-design session. Historical sessions remain in details. The normal UI uses proportional host typography; monospace is reserved for source and identifiers. Account usage is secondary and collapsible.

The document reader starts with purpose, changes, checks, impact and decision meaning. Full Markdown, contract and exact source are separate views. The reading baseline is 16px text, 24px line height and a 700px measure, informed by the inspected Obsidian reading stylesheet. Native TextView does not support CSS; this is a native reading layout, not a claim of identical browser typography. The Markdown preview receives the original terms, inline code and code fences unchanged; native Markdown rendering determines their visual presentation. The 원문 view uses a read-only editor and preserves the exact source. The four reader controls are 쉬운 설명, 전체 설계, 범위·검증 조건 and 원문. The detail header stays compact, and a brief summary identical to the card summary is omitted.

A card and its detail view expose a native status popover with automatic, waiting, in progress and complete choices. Manual status changes the board column while observed execution and pending approvals remain separately visible. Selecting complete expands the completed column immediately. Explicit controls organize, archive and restore a board card. A completed board organization has a distinct label from actual work completion. New design or question content makes an organized card visible again. Native dialogs close by button, Escape and outside press; closing does not submit.

Evidence boundary: native checks exercised status selection, immediate column movement, refresh persistence, popover dismissal, the brief and full Markdown reader including inline code and code fences, and stacked narrow panels. These checks used isolated fixture cards; they did not approve or send a real user's work. Obsidian stylesheet defaults inform the reading measure but do not prove identical native typography or kerning.
