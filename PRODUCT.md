# Product

<!-- impeccable:product-schema 1 -->

## Platform

Native macOS, built as a Herdr GPUI mod. This is not a web page or a mobile application.

## Users

An operator who supervises several teams and wants to understand work and answer requests without visiting every session.

## Product Purpose

Make each card explain its task, responsible person, current session and next decision. Distinguish an operator decision from an operational problem that an agent must investigate.

## Operating Context

The board combines independent work records, native session observations, design documents and durable answer/delivery records. These sources describe separate facts; receiving a message does not prove implementation or completion.

## Capabilities and Constraints

- Current design revision and digest determine which work sessions belong to a card.
- Decisions and approvals retain their existing version, identity and permission checks.
- Board organization is reversible and does not complete work, approve designs or start agents.
- Approved document source stays unchanged. User explanations are separately bound to the document version.
- Theme and native interaction conventions remain integrated with the host application.

## Product Principles

- Put the task and current evidence before technical identifiers.
- Ask the operator only when a concrete choice is available.
- Show unknown or waiting states without claiming execution.
- Preserve terminology while explaining its purpose in plain language.
- Keep implementation history and raw documents available behind deliberate controls.
